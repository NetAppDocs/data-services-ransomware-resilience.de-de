[[deployment]]
== Einsatz

.Benötigen Sie eine Lizenz zur Nutzung von Ransomware Resilience?
Sie können die folgenden Lizenztypen verwenden:

* Melden Sie sich für eine 30-tägige kostenlose Testversion an.
* Erwerben Sie ein Pay-as-you-go-Abonnement (PAYGO) für NetApp Intelligent Services und Ransomware Resilience über Amazon Web Services (AWS) Marketplace, Google Cloud Marketplace und Microsoft Azure Marketplace.
* Bringen Sie Ihre eigene Lizenz mit (BYOL). Dabei handelt es sich um eine NetApp -Lizenzdatei (NLF), die Sie von Ihrem NetApp Vertriebsmitarbeiter erhalten. Sie können die Lizenzseriennummer verwenden, um BYOL im Bereich „Licenses and subscriptions“ der Konsole zu aktivieren.


.Wie aktiviert man die Ransomware-Resilienz?
Auf die Ransomware Resilience kann über die NetApp Console zugegriffen werden. Es ist sicherzustellen, dass die erforderlichen link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-reference-roles.html["Zugriffsrollen"] vorhanden sind und die link:rp-start-prerequisites.html["Voraussetzungen"] erfüllt werden. Nach erfolgreicher Konfiguration eines Console-Agenten kann anschließend link:rp-start-discover.html["Arbeitslasten ermitteln"] werden.

Weitere Informationen finden Sie unterlink:rp-start-login.html["Zugriff auf Ransomware-Resilienz"] Undlink:rp-start-quick-start.html["Schnellstartanleitung zur Ransomware-Resilienz"] .

.Welche Anforderungen gelten für den Console agent bei Ransomware Resilience?
link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-ransomware-roles.html["Die entsprechenden Berechtigungen für Benutzer sind zu überprüfen und festzulegen."]Mindestens ein aktiver Console-Agent in Ihrem Console Unternehmen muss mit einem unterstützten System verbunden sein. Der Console-Agent muss über den  `cloudmanager-ransomware-protection` Container in aktivem Zustand verfügen.

Darüber hinaus gilt eine Beschränkung von 3.000 Workloads pro Console agent. Eine Anfrage zur Erweiterung dieser Beschränkung ist möglich.

.Ist die Ransomware-Resilienz in den Modi Standard, eingeschränkt und privat verfügbar?
Die Ransomware-Resilienz ist derzeit nur im Standardmodus verfügbar.

Eine Erläuterung dieser Modi für alle NetApp -Datendienste finden Sie unter https://docs.netapp.com/us-en/console-setup-admin/concept-modes.html["Bereitstellungsmodi der NetApp Console"^] .

.Wie funktioniert die Abrechnung für Ransomware Resilience?
Sie können Ransomware Resilience mit einer 30-tägigen kostenlosen Testversion ausprobieren. NetApp berechnet Ihnen für die Nutzung der Testversion von Ransomware Resilience keine Gebühren.

Wenn Sie sowohl über Backup and Recovery als auch über Ransomware Resilience verfügen, werden alle gemeinsamen Daten, die durch beide Produkte geschützt werden, nur über Ransomware Resilience abgerechnet.

Wird eine Arbeitslast als geschützt eingestuft, wird sie auf die erworbene Kapazität oder das PAYGO Abonnement angerechnet. Ransomware Resilience stuft eine Arbeitslast als geschützt ein, wenn entweder eine Verschlüsselungs- oder eine Benutzeraktivitätserkennungsrichtlinie aktiviert ist. Ohne mindestens eine dieser Erkennungsrichtlinien wird eine Arbeitslast als gefährdet eingestuft. Gefährdete Arbeitslasten werden nicht auf die erworbene Kapazität angerechnet.

Geschützte Workloads werden nach Ablauf der kostenlosen Testphase auf die erworbene Kapazität oder das Abonnement angerechnet. Ransomware Resilience wird pro GB für die Daten berechnet, die mit geschützten Workloads verbunden sind (wie von ONTAP gemeldet), vor Effizienzsteigerungen.

Bei der Dimensionierung basieren die Lizenzkosten auf der logischen Kapazität des aktiven Dateisystems, unabhängig davon, ob sich diese Daten in Hot- oder Cold-Storage-Tiers befinden. Der von Snapshots belegte Speicherplatz wird in dieser Berechnung nicht berücksichtigt, selbst wenn diese Snapshots in einem Cold-Storage-Tier gespeichert sind.

.Was passiert nach Ablauf meiner Testphase oder nach Ablauf meiner Lizenz?
Nach Ablauf der kostenlosen Testphase oder der Lizenz bzw. des Abonnements bleiben die Workloads in NetApp Ransomware Resilience sichtbar, sofern sie nicht ausgeschlossen werden. Mit einer abgelaufenen Lizenz oder Testphase besteht Folgendes:

* Anzeigen von Workloads und Workload-Integrität
* Löschen von Ressourcen wie Richtlinien
* Führen Sie alle geplanten Vorgänge aus, die während der Testphase oder unter der Lizenz erstellt wurden


Für die Stilllegung von Ransomware Resilience ist eine Supportanfrage erforderlich. Die Anfrage muss Ihre Unternehmen-ID enthalten und vermerken, dass Sie den Dienst stilllegen möchten.

[[interoperability]]
== Interoperabilität

.Ist die Ransomware-Resilienz auf die Schutzeinstellungen in ONTAP vorbereitet?
Ja, Ransomware Resilience erkennt in ONTAP festgelegte Snapshot-Zeitpläne.

.Enthält die Ransomware Resilience Lizenz zusätzliche NetApp Produkte?
Nein, die Ransomware Resilience Lizenz beinhaltet keine zusätzlichen NetApp Produkte.

.Wie interagiert Ransomware-Resilienz mit NetApp Backup und Recovery?
Wenn Sie über eine aktive Backup and Recovery Lizenz sowie Ransomware Resilience verfügen, erkennt Ransomware Resilience die in Backup and Recovery festgelegten Snapshot- und Backup-Richtlinien. Backup and Recovery Richtlinien können in Ransomware Resilience nicht bearbeitet, aber ersetzt werden.

Ransomware Resilience arbeitet auch mit Backup und Recovery zusammen, um eine datei- und workloadkonsistente Wiederherstellung zu ermöglichen. Workloads, die sowohl von Ransomware Resilience als auch von Backup und Recovery erkannt und geschützt wurden, können von jedem der beiden Dienste wiederhergestellt werden.

Wenn Sie sowohl über Backup and Recovery als auch über Ransomware Resilience verfügen, werden alle gemeinsamen Daten, die durch beide Produkte geschützt werden, nur über Ransomware Resilience abgerechnet.

.Was muss ich wissen, wenn ich die Benutzeraktivitätserkennung zuvor über Data Infrastructure Insights Workload Security aktiviert habe?
Wenn Sie bereits NetApp Data Infrastructure Insights (DII) Workload Security verwenden, können dieselben Workload Security Agenten auch für Ransomware Resilience genutzt werden. Es ist nicht erforderlich, separate Workload Security Agenten für Ransomware Resilience bereitzustellen. Die Nutzung derselben Workload Security Agenten setzt jedoch eine Kopplung zwischen der Ransomware Resilience Console Organisation und dem DII Storage Workload Security Mandanten voraus. Für die Aktivierung dieser Kopplung ist der Kontakt mit dem Kundenbetreuer erforderlich.

Wenn Sie die Benutzeraktivitätserkennung in Ransomware Resilience aktivieren, werden die aktuell in Console gespeicherten Anmeldeinformationen zum Managen Ihrer Datensammler verwendet. Falls Sie die Benutzeraktivitätserkennung zuvor über Data Infrastructure Insights (DII) Workload Security aktiviert haben, ersetzen die Anmeldeinformationen von Console die Anmeldeinformationen, die Sie zuvor in DII zum Managen von Datensammlern verwendet haben.



[[workloads]]
== Arbeitslasten

.Was versteht man unter Arbeitslast im Kontext von Ransomware-Resilienz?
Eine Arbeitslast ist eine virtuelle Maschine oder eine Dateifreigabe.

.Wie priorisiert Ransomware Resilience die Workload-Daten?
Die Priorität der Arbeitslast (kritisch, Standard, wichtig) wird durch die Snapshot-Frequenzen bestimmt, die bereits für jedes mit der Arbeitslast verbundene Volume und die geplanten Backups angewendet wurden.

link:rp-use-protect.html["Informieren Sie sich über die Priorität oder Wichtigkeit der Arbeitslast"] .

.Welche Workloads werden von Ransomware Resilience unterstützt?
Ransomware Resilience kann die folgenden Workloads identifizieren: Oracle, Dateifreigaben, Blockspeicher, VMs und VM-Datenspeicher.

.Wie ordnet man Daten einer Arbeitslast zu?
Ransomware Resilience erkennt die Volumes und die Dateierweiterungen und ordnet sie der entsprechenden Arbeitslast zu.

.Was ist eine geschützte Arbeitslast?
In Ransomware Resilience wird eine Arbeitslast als *geschützt* angezeigt, wenn eine _Erkennungs_-Richtlinie aktiviert ist. Die Erkennungsrichtlinie muss entweder die Erkennung von Verschlüsselungen oder von verdächtigem Benutzerverhalten (oder beides) umfassen. Weitere Informationen finden sich unter link:rp-use-protect.html#add-a-ransomware-protection-strategy["Erkennungsrichtlinie"].

.Was ist eine „gefährdete“ Arbeitsbelastung?
Eine Arbeitslast muss über eine Ransomware Datensicherungsstrategie mit aktivierter Verschlüsselungserkennung oder Erkennung des Benutzerverhaltens verfügen, um als geschützt zu gelten. Ohne mindestens eine dieser Erkennungsstrategien wird die Arbeitslast als gefährdet eingestuft. Wenn eine Arbeitslast über eine Backup- oder Snapshot-Richtlinie verfügt, aber keine aktivierte Verschlüsselungserkennung oder Erkennung des Benutzerverhaltens aufweist, gilt sie als gefährdet.

Ransomware Resilience bietet auch eine Erkennung verdächtiger Dateierweiterungen. Wenn die Erkennung verdächtiger Dateierweiterungen die einzige aktivierte Erkennungsrichtlinie ist, wird die Arbeitslast als gefährdet eingestuft.

Zum Schutz vor Ransomware sollten Sie eine link:rp-use-protect.html#add-a-ransomware-protection-strategy["Erkennungsrichtlinie"] aktivieren.

.Ich habe einen neuen Band hinzugefügt, aber er wird noch nicht angezeigt. Was soll ich tun?
Wenn Sie Ihrer Umgebung ein neues Volume hinzugefügt haben, starten Sie die Erkennung der Arbeitslast erneut. Nachdem das Volumen entdeckt wurde, link:rp-use-protect.html#add-a-ransomware-protection-strategy["Schutzrichtlinien anwenden, um das neue Volumen zu schützen"]Die



[[protection-policies]]
== Schutzrichtlinien

.Können Ransomware-Resilienzrichtlinien mit anderen Arten von Workload-Richtlinien koexistieren?
Derzeit unterstützt Backup und Recovery (Cloud Backup) eine Backup-Richtlinie pro Volume. Wenn Sie den Backup-Schutz mit Backup und Wiederherstellung konfigurieren, werden die Backup-Richtlinien mit Ransomware Resilience geteilt.

Snapshot-Kopien sind nicht begrenzt und können von jedem Dienst separat hinzugefügt werden.

.Welche Richtlinien sind in einer Ransomware-Schutzstrategie erforderlich?
A link:rp-use-protect.html#add-a-ransomware-protection-strategy["Ransomware-Schutzstrategie"] erfordert:

* eine Ransomware-Erkennungsrichtlinie und
* eine Snapshot-Richtlinie


Eine Backup-Richtlinie ist in der Ransomware-Resilience-Strategie nicht erforderlich.

.Welche Arten von Angriffen erkennt Ransomware Resilience?
Ransomware Resilience erkennt fünf Angriffstypen:

* Verschlüsselung (Entropie)
* Verschlüsselung (Benutzerverhalten)
* Datenpanne
* Datenvernichtung
* Verdächtige Benutzeraktivität


Weitere Informationen zu link:concept-ransomware-resilience.html#attack-types["Angriffsarten"].

.Ist die Ransomware-Resilienz auf die Schutzeinstellungen in ONTAP vorbereitet?
Ja, Ransomware Resilience erkennt Snapshot-Zeitpläne, die in ONTAP festgelegt sind. Es erkennt außerdem, ob ARP und FPolicy auf allen Volumes einer erkannten Workload aktiviert sind. Die Informationen, die Sie im Ransomware Resilience-Dashboard sehen, werden aus anderen NetApp Lösungen und Produkten zusammengeführt.

.Berücksichtigt die Ransomware-Resilienz die bereits in Backup und Recovery festgelegten Richtlinien?
Ja, wenn Sie Workloads in Backup and Recovery verwalten, werden diese Richtlinien in Ransomware Resilience übernommen.

.Können Sie Richtlinien ändern, die aus NetApp Backup und Recovery übernommen wurden?
Nein, Sie können von Backup und Recovery verwaltete Richtlinien nicht über Ransomware Resilience ändern. Sie verwalten Änderungen an diesen Richtlinien in Backup und Recovery.

.Wenn Richtlinien aus ONTAP vorhanden sind (wie ARP, FPolicy und Snapshots), werden diese durch Ransomware Resilience geändert?
Ransomware Resilience ändert keine bestehenden Erkennungsrichtlinien (ARP- und FPolicy-Einstellungen) von ONTAP. Wenn Sie Einstellungen in Ransomware Resilience ändern, können Sie die ONTAP Einstellungen überschreiben.

.Was passiert, wenn Sie nach der Anmeldung für Ransomware Resilience neue Richtlinien in Backup und Recovery hinzufügen?
Ransomware Resilience erkennt neu erstellte Richtlinien und Richtlinienänderungen in Backup und Recovery.

.Können Richtlinien über ONTAP geändert werden?
Ja, Sie können Richtlinien von ONTAP in Ransomware Resilience ändern.  Sie können in Ransomware Resilience auch neue Richtlinien erstellen und auf Workloads anwenden.  Diese Aktion ersetzt vorhandene ONTAP -Richtlinien durch die in Ransomware Resilience erstellten Richtlinien.

.Kann man Richtlinien in ONTAP deaktivieren?
Sie können ARP in Erkennungsrichtlinien über die System Manager-Benutzeroberfläche, APIs oder CLI in ONTAP deaktivieren.

Sie können FPolicy- und Sicherungsrichtlinien deaktivieren, indem Sie eine andere Richtlinie anwenden, die diese nicht enthält.
